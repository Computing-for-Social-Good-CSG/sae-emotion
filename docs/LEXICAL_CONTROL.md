# Lexical-shortcut control

The additional uploads supply the preprocessing and fixed-steering evaluation for the lexical control. Large activation arrays are not required for this evaluation once selected-feature files and steering checkpoints have been generated by the earlier pipeline.

## 1. Build the filtered, balanced dataset

Use `notebooks/evaluation/01_prepare_lexical_control.ipynb`, or run its exported CPU script:

```bash
python scripts/run.py prepare-lexical-control
```

This needs NumPy, pandas, SciPy, and scikit-learn, but no model or GPU. The optional `preprocessing` dependency group provides these names; use the original environment versions for final reproduction.

The supplied settings are:

- Input: `data/self_reported_ekman_zeroshot_preds.csv`, using `text` and `emotion`.
- Binary lowercase unigram/bigram counts; minimum document frequency 3; maximum document frequency 0.95; token pattern includes single-character word tokens.
- Per-emotion chi-square ranking with target-to-other document prevalence ratio at least 3 and at least 3 target-emotion documents.
- Keep the top 20 terms for each emotion after those filters.
- For the main control, remove every example containing any selected term, regardless of its gold label.
- Balance by sampling each emotion down to the smallest remaining class, with seed 42.

The original notebook also writes a less aggressive label-specific filtering variant. The evaluator uses the **globally filtered, balanced** CSV:

`data/lexical_shortcut_control/balanced_dataset_without_global_lexical_shortcuts.csv`

The offline CPU verification reproduced 1,332 rows (222 per emotion) from the supplied 9,870-row data. Its versions, counts, and output hashes are in `results/validation/lexical_preprocessing.json`. This check verifies dataset construction only, not any model performance.

## 2. Evaluate unchanged steering checkpoints

Use `notebooks/evaluation/02_evaluate_lexical_control.ipynb`. This is the supplied variant with resume support and Gemma Scope cache handling. It is selected for those operational features, not because its displayed scores were higher.

Start a fresh kernel, run the repository setup cell, then run the cache-configuration cell before any Hugging Face imports. Configure `HF_HOME` for the environment if needed. The notebook contains a workaround for SAELens's internal tensor-shape loader; compatibility depends on the installed SAELens version. Its download call can fetch missing files, so it is not an offline-only evaluator.

Required generated files, per model:

- `data/<model>-feature-act[-small]/auto_selected_unique_features_with_affected_emotions.csv`
- `data/<model>-feature-act[-small]/global_feature_steering/<run>/best_feature_steering.pt`

The notebook loads existing checkpoints and evaluates vanilla versus steered predictions. It does not retrain on the lexical-control dataset. Set the run directory to match the actual checkpoint location; the historical directory name `lr_5e-3_l1_0p0` does not establish the training learning rate.

`RESUME = True` skips completed models based on existing result rows. Reuse a result directory only for the same dataset, feature lists, checkpoints, and evaluation settings. Use a new `OUTPUT_DIR` or disable resume when those inputs change; completion checks do not establish input provenance.

## Retained variants and evaluation scope

The original and earlier resume evaluators are in `archive/lexical_control/`. On upload, the steering utility was byte-identical to the original ZIP version and the prompt-robustness notebook had identical cell source. The organized copies subsequently gained explicit shared-split routing/checks as recorded in the migration manifest.

The preprocessing notebook mines n-grams and builds its filtered dataset from the **full combined CSV**. It does not restrict that CSV to a held-out split before filtering. The author has now supplied and confirmed the shared split: the reproduced 1,332-row balanced control contains **403 distinct training prompt texts (404 rows)** and **275 distinct held-out prompt texts (275 rows)**. Exact-match counts and hashes are in `results/validation/split_consistency.json`.

This is a filtered full-corpus diagnostic, not an independent held-out generalization set. The supplied filtering algorithm and evaluation inputs were preserved. A separate held-out control would need a specified protocol and a fresh run; the existing Table A.4 scores cannot be relabeled as coming from that new population.
