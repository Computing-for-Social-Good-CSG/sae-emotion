# Reproduction guide

## Current status

This is an organized source-based release with limited mechanical fixes. Large `.npy` files are intentionally omitted: generate them using the steps below. Final selected features, checkpoints, and results can likewise be generated by running the pipeline. Exact model-score reproduction still needs the original research dependencies and confirmed final settings. CPU lexical preprocessing has been checked; model experiments have not been rerun. Upstream EXPRESS filtering code is outside current scope; use the supplied combined CSV as the starting point.

## Pipeline

1. **Data.** Read `data/README.md`. Use the supplied `data/train_df.csv` (2,400 rows) and `data/val_df.csv` (1,974 rows) for shared steering splits. Do not split the 2,400-row file again. The full combined CSV has `text`, `emotion`, `dataset`, `pred_emotion`, and `input_text`; inference can regenerate model predictions. Never treat `pred_emotion` as ground truth. The full corpus remains the input for feature discovery and the existing full-corpus diagnostic.
2. **Activations.** Configure and run `python scripts/run.py extract-activations`. This writes model predictions, correctly predicted rows (with original row indices), final-token hidden states, and SAE activations into `data/`.
3. **Candidates.** Set the same model/SAE in `select_candidates.py`, then run `python scripts/run.py select-candidates`. Preserve CSV indices because the feature extractor uses them to index the activation array. This stage currently uses correctly predicted examples.
4. **Causal effects.** Set the same model/SAE in `estimate_causal_effects.py`, then run `python scripts/run.py estimate-effects` to deduplicate candidate features and compute per-emotion logit changes.
5. **Core features and graph.** Open `notebooks/rq1_features/03_select_core_features.ipynb`. Use only the cells corresponding to the intended model/SAE. It includes entropy classification, top-k joint ablation, final feature selection, and feature-graph extraction. Resolve the entropy/grid discrepancy before calling this the final paper selection.
6. **Causal validation.** Run `ablate-features`, `patch-activations`, or `adjacent-mediation` through `scripts/run.py` after reviewing each script's model list. The mediation driver also requires graph edges; the other two require final selected-feature tables.
7. **Intervention.** `targeted-amplification` runs the multiplier sweep on the supplied `val_df.csv`, aligned with the author's shared-split confirmation. Use fresh output paths when rerunning it; older targeted outputs used the full corpus. `train-steering` learns global multipliers from the supplied training split and evaluates the shared held-out split, plus **XED and EmoEvent only**. `TRAIN_CSV_PATH`, `VAL_CSV_PATH`, and `MAIN_CSV_PATH` distinguish training, held-out, and full-corpus diagnostic data. When `val_csv_path` is supplied, `val_size`, `max_per_class`, and the seed do not resample either split. Both split files already contain prompted `input_text`, so keep `train_apply_prompt_template=False`. The original API still supports automatic splitting when `val_csv_path=None`. Confirm the final learning rate and checkpoint-selection/reporting protocol; the code continues to select its best checkpoint using `main_val`.
8. **Baselines and evaluation.** Both emotion-vector training variants read the supplied split files; no unsupported best-version choice has been made. The few-shot notebook retains its original demonstration-pool sampling from the full training partition. The prompt-robustness notebook verifies generated run holdouts against the supplied `data/val_df.csv`, then recovers the original sentences from `MAIN_SOURCE_PATH` by exact prompt/label match before applying each template once. This fixes nested main-data prompts. Start a fresh kernel and rerun the GPU evaluation; corrected outputs and table exports go to `data/prompt_robustness_evaluation_raw_text/`. Earlier scores cannot be treated as results of the corrected code. `general-capabilities` evaluates generated steering checkpoints. For the lexical control, first run `python scripts/run.py prepare-lexical-control`, then open `notebooks/evaluation/02_evaluate_lexical_control.ipynb`. See [LEXICAL_CONTROL.md](LEXICAL_CONTROL.md) for parameters, confirmed training overlap, required generated artifacts, and resume behavior. Keep test metrics out of model/layer/checkpoint selection when finalizing the protocol.
9. **Figures and statistics.** Use the RQ3 analysis and paper-figure notebooks after collecting exact final run outputs. Resolve the significance correction scope before regenerating Table A.7.

Each launcher command wraps a research script and sets the working directory and import path. The new lexical-preprocessing script is a direct export of the supplied notebook with a main guard. The launcher itself does not change scientific parameters or submit cluster jobs; the selected stage generates its documented artifacts.

## Expected generated files

For a model identifier with `/` replaced by `-` (the model slug):

- `data/combined_zeroshot_preds_<slug>.csv`
- `data/combined_zeroshot_filtered_<slug>.csv`
- `data/combined_zeroshot_hidden_states_<slug>.npy`
- `data/sae_acts_combined_zeroshot_<slug>.npy` for Gemma-2/Llama; `..._<small|big>.npy` for Gemma-3
- `data/<slug>-feature-act[-small|-big]/core_emotion_features_top0.1_by_avg_activation.csv`
- Corresponding signed-logit, entropy, and top-k joint-ablation CSVs
- `auto_selected_emotion_specific_topk_features.csv`
- `auto_selected_unique_features_with_affected_emotions.csv`
- Graph-edge tables and ablation/patching/mediation summaries
- `global_feature_steering/<run>/config.json`, `train_df.csv`, `val_df.csv`, `best_feature_steering.pt`, `epoch_metrics_long.csv`, `epoch_per_emotion_f1.csv`, and multiplier exports

Historical notebooks may still contain paths for a different model, SAE size, or exploratory output. Review the relevant cells before execution. Three Python entry points were made consistent about SAE suffixes; scientific selection logic was not changed.

These large intermediate files and checkpoints remain ignored by Git. They do not need to be copied into GitHub. Keep sufficient local disk space for the extraction outputs and retain the same dataset row ordering between activation extraction and feature selection.

## Recovering the original environment and runs

The author-supplied cluster report and all 245 package versions are now in `environment/`; direct dependency pins are in `requirements/`. Use the existing Python 3.11.14 cluster environment when available. Follow [ENVIRONMENT.md](ENVIRONMENT.md) for details and the unrecorded GPU/driver information. `python scripts/collect_environment.py` can refresh the report inside a GPU session. A notebook cell using `sys.executable` can ensure that a new report comes from the actual experiment kernel.

When rerunning each of the seven models (eleven analysis settings), save stable row IDs or hashes for splits, seeds, selected features, model/SAE identifiers, full-precision metrics, chosen checkpoint/epoch, and external evaluation outputs. The supplied shared split hashes and CPU consistency checks are now recorded in `data/manifest.json` and `results/validation/split_consistency.json`. Sharing compact reference outputs is optional; model-specific final run configurations and checkpoint provenance remain unverified.
